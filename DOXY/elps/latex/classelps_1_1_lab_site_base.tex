\subsection{Detailed Description}
Base class for handling user defined data on a given S\-I\-T\-E.\par

\begin{DoxyItemize}
\item In a M\-A\-S\-S A\-C\-T\-I\-O\-N context, the sites can be stored in an array (See \hyperlink{classelps_1_1_lab_array_binding}{Lab\-Array\-Binding}).\par

\item In a S\-P\-A\-T\-I\-A\-L\-I\-Z\-E\-D context, the sites would be stored in the node of a network (See \hyperlink{classelps_1_1_lab_net_binding}{Lab\-Net\-Binding}).\par

\end{DoxyItemize}

This class is specialized in managing 2 stacks of A\-T\-T\-R\-I\-B\-U\-T\-E\-S (See \hyperlink{classelps_1_1_lab_attributes_stack}{Lab\-Attributes\-Stack}).
\begin{DoxyItemize}
\item The first one stores the attributes related to the I\-N\-D\-I\-V\-I\-D\-U\-A\-L currently residing on the S\-I\-T\-E.\par

\item The second one stores the attributes related to the S\-I\-T\-E itself (typically, if the individual moves or dies, those attributes would persist...).
\end{DoxyItemize}

It's state (the state of its attributes at a given time) can be binarized/dumped by implementing the features inherited from the \hyperlink{classelps_1_1_lab_i_binarizable}{Lab\-I\-Binarizable} interface (See \hyperlink{classelps_1_1_lab_site_base_a42e30841600ed1e45dcd2c1c2a3071e8}{Binarize()}, \hyperlink{classelps_1_1_lab_site_base_ad1b2721336db27de86213769b78d3ccd}{Un\-Binarize()}).

It manages also a stack of states. A S\-I\-T\-E can switch from one state to another.

S\-T\-A\-T\-E\-S (See also \-: \hyperlink{classelps_1_1_lab_state_stack}{Lab\-State\-Stack}) \-:\par
 A state (like A\-T\-T\-R\-I\-B\-U\-T\-E\-S) can change in time. The differences are \-:
\begin{DoxyItemize}
\item It can have only integer values \mbox{[}0..N\mbox{]}
\item They can be linked to each other (by giving the id of the next state coming after the current one)
\item They can have a limited life time -\/ optional timeout -\/ before returning to an other specified state
\end{DoxyItemize}

{\bfseries Note \-:} A Site is {\bfseries always} related to a simulator.

\subsection*{U\-S\-A\-G\-E \-:}

A basic use case would look like follows \-:


\begin{DoxyCode}
\hyperlink{classelps_1_1_lab_site_base_ab051b072f05ac8a16bd51a2331c8ba8c}{LabSiteBase} *a\_site = \textcolor{keyword}{new} \hyperlink{classelps_1_1_lab_site_base_ab051b072f05ac8a16bd51a2331c8ba8c}{LabSiteBase}(sim);             \textcolor{comment}{
      // 'sim' : the related simulator}

\textcolor{comment}{// ATTRIBUTES}
\textcolor{comment}{// Indexed attribute : here, 3 sets/groups are created ("pop0", "pop1", "pop2")}
\textcolor{comment}{// [In case the site was registered by the <b>Sets Manager</b> (See
       LabSiteSetsManager, LabSiteSetsCalculator)]}
a\_site->PushAttribute(\textcolor{stringliteral}{"pop"}, LabSiteBase::IND\_DEP, \textcolor{keyword}{true}, 3);
\textcolor{comment}{// Classical attributes (doubles)}
a\_site->PushAttribute(\textcolor{stringliteral}{"x"}, LabSiteBase::IND\_DEP);
a\_site->PushAttribute(\textcolor{stringliteral}{"m"}, LabSiteBase::IND\_DEP);

\textcolor{comment}{// STATES}
\textcolor{comment}{// We define 3 possible states :}
\textcolor{comment}{// Parameters : 1, -1, -1 => next\_id = 1, timeout\_id = -1, timeout = -1.0}
a\_site->PushState(\textcolor{stringliteral}{"EMPTY"},    1, -1, -1);
a\_site->PushState(\textcolor{stringliteral}{"RESIDENT"}, 1, -1, -1);
a\_site->PushState(\textcolor{stringliteral}{"MUTANT"},   1, -1, -1);

\textcolor{comment}{// Choose whether the current site is in EMPTY or RESIDENT state from the}
\textcolor{comment}{// probability 'p\_init'.}
\textcolor{keywordflow}{if}(rng->GetNextDouble() < p\_init)
\{
        \textcolor{comment}{// This site will be a member of the "RESIDENT" set}
        a\_site->SetState(BdmLsim3::RESIDENT, GetTime());

        a\_site->SetAttrDouble(LabSiteBase::IND\_DEP, BdmLsim3::POP, 1);
        a\_site->SetAttrDouble(LabSiteBase::IND\_DEP, BdmLsim3::X, x1);
        a\_site->SetAttrDouble(LabAttributesStack::IND\_DEP, BdmLsim3::M, mo1);

        popcnt++;
\}
\textcolor{keywordflow}{else}
\{
        \textcolor{comment}{// This site will be a member of the "EMPTY" set}
        a\_site->SetState(BdmLsim3::EMPTY, GetTime());

        a\_site->SetAttrDouble(LabSiteBase::IND\_DEP, BdmLsim3::POP, 0);
        a\_site->SetAttrDouble(LabSiteBase::IND\_DEP, BdmLsim3::X, 0.0);
        a\_site->SetAttrDouble(LabSiteBase::IND\_DEP, BdmLsim3::M, 0.0);
\}
\end{DoxyCode}


{\bfseries Note } about {\bfseries Sets Management} \-:

As mentioned in the source code above, in case the site was registered by the {\bfseries Sets Manager}, Indexed attribute would result in the creation of related sets / groups (ex. 3 groups \mbox{[}\char`\"{}pop0\char`\"{}, \char`\"{}pop1\char`\"{}, \char`\"{}pop2\char`\"{}\mbox{]} are created from the indexed attribute \char`\"{}pop\char`\"{}...) -\/ See \hyperlink{classelps_1_1_lab_site_sets_manager}{Lab\-Site\-Sets\-Manager}, \hyperlink{classelps_1_1_lab_site_sets_calculator}{Lab\-Site\-Sets\-Calculator} for more details concerning Sets.
