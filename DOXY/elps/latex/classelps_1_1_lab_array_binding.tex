\subsection{Detailed Description}
This class embeds a list of sites and provides features to populate it (for use in a {\bfseries M\-A\-S\-S A\-C\-T\-I\-O\-N} context).

All the {\bfseries $\ast$\-Array} sub-\/classes of the simulator (See \hyperlink{classelps_1_1_lab_simulator_base}{Lab\-Simulator\-Base}) also inherit from \hyperlink{classelps_1_1_lab_array_binding}{Lab\-Array\-Binding} (See, for example, \hyperlink{classelps_1_1_lab_simulator_time_array}{Lab\-Simulator\-Time\-Array} for an illustration of this).

\subsection*{U\-S\-A\-G\-E \-:}

First you will need an {\bfseries array based} simulator \-:


\begin{DoxyCode}
\textcolor{keywordtype}{int} pop\_max = 10000;
LabSimulatorTimeArray *sim = LabSimulatorTimeArray();        \textcolor{comment}{// Get yourself a
       simulator}
sim->SetMaxPopulationSize(pop\_max);                          \textcolor{comment}{// Set the
       simulator's capacity}
\end{DoxyCode}


Then fill the array binding with the corresponding number of sites. The array must contain as many Sites as the simulator's capacity (10000 in the above example). For this you can use ready made ones (ex. \hyperlink{classelps_1_1_lab_site_base}{Lab\-Site\-Base}, ... or derivatives) and assign them manually. But, \hyperlink{classelps_1_1_lab_array_binding}{Lab\-Array\-Binding} provides methods to ease the filling of the array from {\bfseries sites model objects} (See Lab\-Array\-Binding.\-Populate() functions).

Another big advantage of using those methods is that it turns on the {\bfseries Sets Manager} (See \hyperlink{classelps_1_1_lab_site_sets_calculator}{Lab\-Site\-Sets\-Calculator}, \hyperlink{classelps_1_1_lab_site_sets_manager}{Lab\-Site\-Sets\-Manager} ...).

The usages are pretty much same as in \hyperlink{classelps_1_1_lab_net_binding}{Lab\-Net\-Binding}.

{\bfseries The half-\/manual way \-:}


\begin{DoxyCode}
sim->BeginSetSites(pop\_max);                                \textcolor{comment}{// Mandatory to
       open the sites in writing}
...
LabSiteBase *a\_site = \textcolor{keyword}{new} LabSiteBase(sim);                 \textcolor{comment}{// Create a Site}
sim->SetOneSiteAt(a\_site, 0);                               \textcolor{comment}{// Mandatory to
       assign a site to a specified location in the}
...                                                         \textcolor{comment}{// array (this
       enables the Sets Manager to monitor the Site)}
...
...                                                         \textcolor{comment}{// Repeat the above
       for EVERY single site}
...
sim->EndSetSites();                                         \textcolor{comment}{// Close the sites
       in writing}
\end{DoxyCode}


This allows to customize each site on the fly, but keep in mind that every single site in the array has to be assigned before closure.

{\bfseries The automated way \-:}


\begin{DoxyCode}
vector<LabSiteBase *> models;
LabSiteBase *a\_model = \textcolor{keyword}{new} LabSiteBase(sim);
model\_sites.append(a\_model);                                \textcolor{comment}{// Do this for each
       different kind of site you need}
...
int d[] = \{2000, 8000\};                                     \textcolor{comment}{// Define a
       distribution (here 2 models to be spread)}
vector<int> dist(d, d + \textcolor{keyword}{sizeof}(d) / \textcolor{keyword}{sizeof}(\textcolor{keywordtype}{int}) );          \textcolor{comment}{// Batch assignment
       (spread) of the sites over the network}
sim->Populate(nb\_sites, dist, model\_sites, \textcolor{keyword}{true});
\end{DoxyCode}


{\bfseries Note \-:} Lab\-Array\-Binding\-::\-Populate() functions take in charge everything for you. Your role is restrained to the creation of the models, and the choice of the spreading method.
